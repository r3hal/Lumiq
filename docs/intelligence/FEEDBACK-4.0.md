Focal Intelligence Lab is compiled only in Debug or with `FOCAL_EVALUATION` (`ios-evaluation` on Codemagic). Photo import is explicit through PhotosPicker. The new feedback system never records live frames automatically.

Import an example → label it → evaluate → use “Label this evaluated recommendation” → select Helpful, Incorrect, Unnecessary, Impossible to follow, Made composition worse, or Wrong subject selected. Feedback evaluates the displayed stored-image result; it does not pretend to reproduce a prior live-camera instruction.

Self-contained JSON schema version remains 1 with additive optional fields, so older datasets continue decoding. `samples[].feedback[]` contains UUID, createdAt, label, sampleID, imageSHA256, intent, petStyle, the complete evaluated `result`, source (`consented image evaluation`) and appVersion. `result` includes the actually selected subject/detections, action/text, assessment (including exposure, motion and reliability where available), optional analyzer/paired-decision timing and static crop proposal. Images are normalized JPEGs under `samples[].imageData` (base64 via Codable); labels and outputs share the UUID/hash. No account, serial number, device ID, location or network telemetry is added. Dates use Foundation's default Codable date format (seconds since 2001-01-01 UTC). Bounds are normalized with top-left origin; expected boxes are reference labels only.

`livePerformance`, when available at the moment of explicit export, holds real measured session aggregates: camera source, sample count, means for Vision/decision/observation age, updates per second, stale rejections and thermal state. It has no image data or identity. Blank metrics mean unavailable. Export to the Files/share sheet is user-directed. The self-contained file intentionally includes the imported photos; review it before sharing.

Stored feedback is local, bounded to 100 records per example and 100 examples. Prepare a new export after adding labels. No auto-training, hidden upload or learned adaptation occurs. Developers can group these labels by action/intent/style/confidence and capture session; calibrate on calibration scenes and assess once on independent held-out scenes. A “wrong subject” label should prompt detector/selection investigation, while “unnecessary” with correct localization should prompt recommendation-threshold investigation. Timing and aesthetics alone cannot validate usefulness.
