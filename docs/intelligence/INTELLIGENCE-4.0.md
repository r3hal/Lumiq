Focal 2.4 / build 23 extends the existing guidance pipeline. This report separates implemented code from physical-device evidence. Native compilation, real-image comparison and iPhone 16 Pro Max performance remain unverified in this Linux workspace.

1. **Initial architecture.** AVFoundation's native preview stays independent of serial, bounded analysis. A copied frame is reduced to 640px for Vision detection/tracking; localized identity crops use higher-resolution input. Native face/human rectangles, cat/dog recognition, saliency, rectangles, image classification, text and optional pose provide evidence. Selection has acquisition/challenger dwell and manual selection. Projected observations feed scene/layout search, a minimum-gain crop search, framing/zoom, measured assessment, feasible guidance and temporal memory. Sony JPEGs enter the same analysis after real transport decoding. Existing cancellation generations, lens limits and pinch priority are reused.

2. **Weaknesses found.** Recommendation memory tracked one issue value and could retain an obsolete direction while confirming a different issue. It lacked cross-factor regression checks. The pet profile did not express close-up/environmental/action intent. Low confidence was suppressed live but standalone decision callers still produced generic text. Freshness was checked after Vision, leaving later planning/Coach work outside the final age check. Optional pose requests ignored thermal state. Per-model duration/update frequency were unavailable. Evaluation still compared against 2.2 rather than the immediately preceding recommendation stage. The latest observed native build failures were duplicate baseline types and a dataset-import scope error, fixed in 2.3.1/2.3.2; no later successful Xcode result is available here. Broad object localization remains an actual limitation. Legacy class-name advice helpers remain compatibility code; they are not used by current live guidance.

3. **Algorithms improved.** `PhotographicReasoner` builds supported action candidates, records measured evidence/rejections, ranks by issue priority then expected gain and support, and selects one instruction. Motion suppresses movement commands. Observed clipping/head margins take priority over severe highlights, roll, optional light and small placement/crop adjustments. Composition predictions still come from existing visible-pixel/crop/layout geometry. A candidate needs support ≥0.55 and gain ≥0.08; engineering scores are uncalibrated estimates. Existing explicit manual targets remain honored. A crop that concentrates measured clipping above 0.20 and increases it by more than 0.08 is rejected. Full-frame clipping is sampled once per search.

4. **Files changed.** New: `Composition/PhotographicReasoner.swift`, `PetFramingStyle.swift`, `GuidanceTimingAccumulator.swift`; `Evaluation/BaselineReasoning30.swift`, `EvaluationFeedback.swift`, `GuidancePerformanceReport.swift`; `FocalTests/Intelligence40Tests.swift`; baseline/source/report documents. Updated: `CompositionAssessment`, `AutomaticGuidance`, `GuidanceObservation`, `RecommendationMemory`, `IntentCompositionSearch`, `PreviewFramePolicy`, `CameraController`, `SubjectTracker`, AI settings persistence/view/wiring, developer evaluation models/store/runner/view, project generator and validation script. Settings shows version 2.4 and passes the existing camera into the developer lab. No Sony transport/protocol files changed; capture/RAW/rendering/editor/gallery/manual controls were not rewritten.

5. **New reasoning capabilities.** Candidate diagnostics explain why each action was eligible or rejected. Visibility, exposure, movement, context and intended framing can suppress a superficially useful crop. Secondary subjects/enclosing frames remain protected by existing search. Edge texture alone never commands isolation. A good visible composition remains acceptable without exact centering. Whole-scene landscape/architecture evaluation remains available without a fake object. Logical states are explicit: searching, acquired, evaluating, adjustment, stabilizing, ready and insufficient confidence. They map onto the existing camera screen rather than introducing new screens. This is limited visible-scene reasoning, not unseen-viewpoint prediction or artistic omniscience.

6. **Pets.** AI Photography → Focal Intent → Pet exposes persisted Automatic, Close-up, Whole body, Environmental and Action framing. Close-up evaluates a fresh, observed head envelope while permitting an intentionally cropped body; missing/expired head evidence makes guidance silent. It never invents ears, a face or missing joints. Whole body protects observed body margins/joints. Environmental/action use a lower minimum visible area (0.008) and preserve surroundings/movement space. Neither assumes clutter is bad. Close-up/environmental/action pause automatic cropping; automatic/whole-body retain existing safe zoom. Native cat/dog detector weights are unchanged; improved recognition accuracy is not claimed. Animal head/pose reliability needs actual cat images.

7. **Stability and outcomes.** Memory stores the starting assessment/action/issue/time/subject/intent and compares later observations. Two observations of new clipping, materially worse highlights (>0.12 increase), or loss of previously observed head evidence withdraw an active adjustment and reassess. These are correlations, not evidence that the user followed advice. Existing cumulative issue worsening, cooldowns, opposite-direction dwell and crop-reversal neutral hold remain. A pending unrelated problem withdraws an obsolete direction rather than continuing it. Duplicate timestamps do not advance evidence, including when intent changes. Successful alignment/readiness still clears an adjustment immediately. Identity continuity remains class/bounds tracking, not true instance re-identification.

8. **Automatic zoom.** The existing measured improvement, full subject/context fit, lens/detail limits, stable gyro/observed slow subject, hold and one-ramp-per-scan rules remain. The new gate also checks assessment reliability, observed margins/head clipping and severe subject highlights/darkness. New uncertainty or clipping during a ramp cancels it. Pet framing can prohibit automatic cropping. Freshness is rechecked before ramp eligibility and before final guidance publication; stale work clears instructions and cancels an active ramp. Manual pinch cancellation remains immediate in the existing path. Sony lens zoom stays manual. No optical-quality or greatest-composition guarantee is made.

9. **Models.** No weights, cloud AI or training dependency were added. Vision animal recognition supplies cats/dogs; localized classification has a broad vocabulary but is not a general localized detector. Plain desks, small trees, unfamiliar products and obscured pets can still be missed. Existing Apple image aesthetics on iOS 18+ remains supplementary for stored-image evaluation only. Previously investigated candidates: [Apple model catalog](https://developer.apple.com/machine-learning/models/), [Apple YOLOv3 model card](https://huggingface.co/apple/coreml-YOLOv3) (MIT-labeled card), and [Ultralytics Core ML export](https://docs.ultralytics.com/integrations/coreml/) with [AGPL/enterprise licensing](https://www.ultralytics.com/license). These are research options, not integrated artifacts. Exact chosen categories, input dimensions/orientation, boxes/scores output contract, artifact license, model size and measured latency/heat on this phone must be verified before any adoption. A learned ranking study needs consented subject/intent/action/candidate rankings across diverse scenes and capture-session-separated held-out images. No suitable trained ranking model or dataset is available here. Add a model only after reviewed failures demonstrate that detector coverage, rather than decision policy, is the bottleneck.

10. **Checks performed.** Structural validation passes: deterministic generated Xcode project, all 83 app and 24 test sources registered, no duplicate module-level type names, lexical delimiters, JSON/plist/XML/assets, YAML/build shell syntax, unchanged Sony sources and whitespace. Frozen-source provenance is recorded for 3.0. There are 339 registered XCTest functions, including 25 new regression tests. None executed here. Simulator test and Release device archive attempts both return exit 127 (`xcodebuild: command not found`). Structural validation is not Swift parsing/type checking. Codemagic retains simulator tests as a required step.

11. **Before/after results.** No measured accuracy delta, passing-test count, contradiction reduction or speed gain is available. Those values are null in `BASELINE-STATUS.json`. The lab now compares frozen 2.3.2/Intelligence 3.0 recommendation and memory stages with 4.0 using the same current detections, selected subject, assessment and candidate plan. It isolates those stages; it does not reconstruct a historical detector/planner. The new deterministic baseline regression asserts that a new exposure issue formerly retained pan advice and now withdraws it, but its XCTest execution is pending. Held-out reports require user-reviewed photos; the single landscape starter needs confirmation, and zero annotated cat examples are supplied. Selection overlap is a sequence continuity diagnostic, not ground-truth tracking accuracy; static unwanted crop proposals are not real ramp failures.

12. **Performance.** Live developer diagnostics measure monotonic-clock Vision detection/tracking time, recommendation-stage time, total observation age, valid update frequency and stale rejection count using constant-size aggregates. Lab displays them and explicit export includes them. Observation age excludes final main-thread display delay. Thermal admission intervals: nominal 0.25s, fair 0.40s, serious 0.80s, critical 1.50s (shared processing also throttles). Optional poses pause at serious/critical; critical uses tracking without new acquisition, and landscape classification obeys the same restriction. Native preview/capture cadence is not throttled by these AI settings. Actual iPhone latency, FPS, energy/heat and Sony network quality remain unmeasured. Paired static evaluation timing covers both old/new recommendation stages separately from the shared image analyzer; it is not an old/new inference benchmark.

13. **Limits and feedback.** Universal object detection, gaze/pose intent, unseen backgrounds, semantic distraction judgments and a guaranteed best composition are not implemented. Confidence is a conservative engineering support score, not calibrated correctness probability. Close-up may stay silent when Vision lacks a reliable head envelope. Live gyro/movement/occlusion, RAW/lens behavior and Sony frame quality require hardware. Developer-only feedback is opt-in on an explicitly imported/evaluated image. Six labels are linked to image UUID/hash, selected subject, intent, pet style, measured metrics/exposure, actual recommendation, evaluation timing and label time. No live photographs are silently captured by the new feedback system. Export intentionally contains the imported JPEGs; only the user shares it. It records observations and does not train/adapt a model. See `FEEDBACK-4.0.md` for format.

14. **Exact iPhone test steps.** In Codemagic select repo `r3hal/focal-private`, branch `main`, workflow `ios-sideload` for normal use or `ios-evaluation` for the developer lab. Start a new build; do not reuse the prior IPA. Confirm simulator tests and archive succeed. Download `Focal-unsigned.ipa`, transfer it to Files on the iPhone, open AltStore → My Apps → +, select the IPA and install/update using your existing AltServer setup. Open Focal and confirm Settings says 2.4. Enable AI Guidance; select Pet and try each framing style with your cat in good light, first stationary and then moving. A comfortably framed cat on its bed should stop receiving isolation/pan instructions; a clipped observed head/body should ask for room, except intentional body cropping in Close-up. Environmental/Action must not autozoom. With Automatic framing and zoom enabled, try a small stationary subject, hold steady and pinch during any ramp to check cancellation. Switch AI off and confirm boxes/AI instructions/AI zoom stop. Check off-center people, a landscape, perspective architecture and two subjects. In the evaluation build open … → Camera Settings → Developer Intelligence Lab after 15–30 seconds of live guidance to view real diagnostics. Import photos you consent to share, label subject/region/intent/style/issue/preferred action/split, and save. Mark genuinely held-out scenes before evaluating. Run evaluation, label individual recommendations, prepare a fresh self-contained JSON export, then share only if desired. Use distinct annotated frames and sequence timestamps for temporal tests. Report any build's first `error:` line or export actual results; no improvement should be claimed until these checks are completed.
