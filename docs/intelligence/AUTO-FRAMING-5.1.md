Focal 2.5.1 / build 24 — Intelligence 5.1 automatic shot framing

This updates the existing `FramingPlanner` and `CameraController` ramp. The starting repository was commit `852c861` (Intelligence 4.0); it already contained real AVFoundation zoom, measured crop search and manual pinch cancellation. There was no separate implemented `ShotPlan` type. The new `AutomaticShotPlan` is immutable geometry and verification data used by that existing pipeline, not a second camera controller.

The audit found that motor completion immediately called `framing.finish()` without checking the achieved composition. Target changes during hold/ramp could move the chosen mark. Some settings resets could re-arm after manual override. Zoom observations could describe a later poll rather than the frame admitted for analysis. A single rate ramp supplied no explicit final verification period. Those paths are changed below. No native build or physical-device result is available from this Linux workspace.

1. **Trigger.** With iPhone AI Guidance enabled, Automatic Zoom enabled (its existing default), subject tracking enabled and an armed guidance session, the existing planner must select a measured useful crop. Aiming uses the pre-zoom target `0.5 + (desiredPosition - 0.5) / scale` in each axis. This compensates for real camera zoom expanding around the sensor center. Both tracked alignment and stable camera/subject movement are required throughout the configured hold. At the trigger, a complete shot geometry must pass safety checks; then the existing hardware ramp starts automatically. No request to walk closer is added. Missing, unsafe or already-good plans preserve the current framing. Explicit Center/Thirds choices and an explicit Automatic Zoom opt-out remain respected.

2. **Target factor.** The scene/crop evaluator chooses a measured crop, constrained by intent, visible subject/context and quality limits. The available candidates now also include `sqrt(intentMinimumArea / observedSubjectArea)` when supported, allowing a continuous geometric scale alongside discrete search candidates and actual lens stops. This is an intent-specific heuristic, not a claim to an objectively greatest shot. `targetDisplayedZoom = currentDisplayedZoom × selectedCropScale`. Hardware zoom is `targetDisplayedZoom × zoomMultiplier`, using the actual virtual-camera multiplier. The shot stores starting/desired bounds, centered framing rectangle, target/current scale, observed head/joint/context regions and maximum zoom. An off-center shot is accepted only when aiming projects the subject onto its chosen final mark. Example: a selected scale of 1.65 from current displayed zoom 1.3 yields 2.145, subject to actual device/quality limits; that is not a universal prescribed zoom.

3. **Tracking.** Vision's current subject remains selected; expensive new selection is suspended during the ramp. Real zoom samples are copied through a lock into each admitted iPhone analysis frame, so later polling does not overwrite that frame's factor. The existing tracker seed is reprojected by `newZoom / previousBoundsZoom` through the same native/visible preview mapping. Mirroring/aspect-fill continue using `PreviewProjection`. Observed head/joint envelopes are geometrically transformed with the tracked body; this preserves prior evidence but is not new pose inference. Fresh confidence must stay at least 0.65, and unexpected normalized displacement over 0.12 cancels. Instance re-identification and independently tracking every context object are not newly implemented; strong camera stability and conservative protected geometry remain required.

4. **Ramp control.** `AVCaptureDevice.ramp(toVideoZoomFactor:withRate:)` remains the only automatic lens mechanism. One frozen target is sent. A bounded rate profile starts slowly, increases at 15% progress, and slows at 72%; it never changes targets every frame. `videoZoomFactor` is observed every 50ms. The actual device's acceleration, rate transitions and lens handoffs are hardware-dependent, so this is not a verified cinematic easing curve. Start and ongoing checks use supported maximum/active-format constraints; the initial target also respects minimum available factor and configured quality budget. Critical thermal state cancels. A 1.1-second missing-verification watchdog and 7-second overall deadline cancel safely without declaring success. No SwiftUI scaling or alternate capture framing was introduced. Both preview and capture use the camera's real zoom; existing selected-aspect processing and RAW full-sensor storage semantics remain.

5. **Clipping protection.** The trigger requires the projected subject, observed head/joints, secondary subjects and enclosing context to remain inside safe margins. During each accepted analysis update, the current bounds and remaining projection to the target must still fit. Frozen observed context stays protected; head/joint envelopes follow the tracked body transform. Existing exposure/reliability/low-light checks remain. Uncertain tracking, excessive motion, stale frames, unexpected displacement, unsafe remaining crop, hardware limits or missing shot geometry stop the ramp. These checks depend on accurate detections and cannot guarantee that an undetected ear or hidden limb is preserved. Pet Close-up can now automatically frame when observed head and full protected geometry permit it. Environmental/Action framing retains its existing no-auto-crop policy to preserve intent/context.

6. **Manual override.** Pinch, manual zoom buttons, a selected subject change, composition/intent/Auto-Pro mode changes, explicit lens or front/back camera changes, and AI off cancel camera ownership. A persistent camera-queue block plus analysis-queue armed state prevent unrelated preference resets from re-enabling a cancelled shot. Interrupting an active automatic ramp also disarms it. The generation check rejects queued work from before cancellation. Only explicit new-session actions release the block: AI off then on, an explicit Automatic Zoom off/on choice, or the existing `findSubject` service entry point. In the current UI, use the yellow AI button off/on to start another automatic shot after override. Normal manual controls and autofocus remain available.

7. **Completion.** A motor reaching its target is insufficient. The first observation within desired geometry pauses the physical ramp immediately; it cannot restart during confirmation. Loss of the achieved geometry cancels instead of hunting. Two distinct fresh tracked observations at least 0.2 seconds apart must verify actual zoom above the starting factor and no more than 2% over the planned maximum, width/height within 8% of planned bounds, position within 0.05 normalized aspect-correct distance, stable camera and protected crop geometry. Observed framing may finish before the original target factor if the desired geometry is already achieved, preventing unnecessary enlargement. Then the stopped shot is marked verified and automatic zoom is disarmed. Once the existing readiness state is stable, guidance shows **Shot ready** and suppresses further tightening/pan advice for that verified framing. A lost or interrupted shot is not marked verified. Successful completion and cancellation both prevent zoom hunting/restarts until a new session.
