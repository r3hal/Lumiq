Focal 2.5.2 / build 25 — premature readiness and blocked automatic zoom fix

1. Why READY appeared early

The audit found `FramingPlanner.update` marked `.framed` after a stable hold when `allowZoom` was false. That boolean can be false temporarily because there is no measured plan yet, lighting/tracking is unsafe, or supported crop options are unavailable. `.framed` prevented another ramp attempt in the session. `AutomaticGuidance.update` then permitted Ready to shoot when the geometric reading was ready and the reasoner had no significant action. That described centering/stability, not successful automatic framing. The controller now gates the published reading as well as the guidance message, covering the card, haptic and smart-shutter consumers.

These are demonstrated source paths that can explain the reported behavior, not a recorded reproduction on an iPhone. No current reference recording was available with this request; the pasted requirements were inspected.

2. Why zoom could remain blocked

The consumed-shot path above could prevent the later valid shot from starting. Initial `CameraView.configureCamera` calls to setMode/setIntent also unconditionally registered manual override, including when reopening the view with guidance already enabled. Those saved-configuration calls now use `userInitiated:false`; real user changes still cancel ownership. Explicit Automatic Zoom opt-out, tracking-off, quality/device caps, safe crop and movement checks remain respected. Automatic composition, tracking and Automatic Zoom already default on; AI Guidance remains the existing explicit yellow-button toggle.

A start at displayed 2.5 is not categorically blocked. Targets use currentDisplayedZoom × measuredCropScale, within actual supported/quality limits. Native factor and displayed factor were already related by the virtual-camera multiplier; the factor itself was not proven to be the device fault. The new typed mapping/tests and diagnostics make that distinction explicit. Initial analysis zoom now uses the actual clamped device value rather than assuming 1.

3. Changed implementation

`FramingPlanner.update` has a strict production shot-plan path: no plan or a temporary zoom gate cannot consume the shot. Valid alignment/hold still starts the existing ramp. `confirmCurrentFrame` permits measured no-zoom readiness only after a stable dwell; invalidated measurements clear it. `verifyShot` adds VERIFYING_FRAMING and requires fresh camera telemetry and a stopped motor before confirmation.

`AutomaticShotPlan.achieved` requires the actual displayed factor to be within 2% of the planned target, in addition to size/position/crop checks. The previous early-geometry shortcut below target is removed for this correction.

`ShotReadiness.swift` adds readiness policy, explicit lifecycle labels, camera-factor observations/mapping and development diagnostics, not another camera controller. Lifecycle labels map the existing states to DISCOVERING, SHOT_SELECTED, AIMING, ALIGNED, AUTO_ZOOMING, VERIFYING_FRAMING, READY; PAUSED describes manual override/interruption. A selected-plan decision can advance to aiming on the same accepted frame; logs include selected plan geometry at each transition.

`CameraController` uses native-factor/ramp observations with each analysis frame, retains the subject through both ramp and verification, freezes tighter targets during aiming, and lets no-zoom layouts continue measured evaluation. It gates published `.ready` while completion is unverified and uses the same pipeline for actual zoom supervision. `CameraView.configureCamera` separates restoration from manual actions; `CameraGuidanceCard` treats verification as in-progress. Existing manual pinch/button/AI-off cancellation remains active. Version/build, project registration and validation documentation are updated. Sony protocol/connectivity sources and camera layout are unchanged.

4. Target calculation

The existing measured composition search selects a supported crop using intent, subject bounds/aspect, scale/position/visibility, observed context and quality/device budgets. Its geometric candidate includes sqrt(intentMinimumArea / observedSubjectArea). A plan may choose a different supported candidate based on actual measured improvement. Aiming uses 0.5 + (desiredPosition - 0.5) / selectedScale to put the subject on its final mark after center-based zoom. targetDisplayedZoom = currentDisplayedZoom × selectedScale. The actual AVFoundation target is targetDisplayedZoom × zoomMultiplier. A displayed 2.5 on a virtual device with multiplier 2 means native factor 5; native 2.5 on that device means displayed 1.25. Neither means every factor is optical. Existing conservative quality limits may legitimately refuse a crop; diagnostics identify those gates rather than claiming completion.

5. Real camera control and retention

The existing camera queue locks the actual `AVCaptureDevice` and calls `ramp(toVideoZoomFactor:withRate:)`. Minimum, available maximum, active-format maximum, lifecycle/generation, crop safety, quality, freshness and thermal checks remain. The bounded three-stage rate profile keeps a single target. Native factor and isRampingVideoZoom are polled every 50ms while supervised; observations copied to analysis have a 0.3-second freshness requirement for completion. They are sampled telemetry, not sensor-timestamp metadata. The current Vision selection is reseeded through the existing field-of-view/preview projection, including mirroring/aspect fill. Observed head/joint/context geometry stays protected. Reliable confidence, fresh frames, stable camera and safe remaining crop are required. Subject loss or unsafe geometry cancels without claiming readiness.

6. READY gate

For a zoom shot, actual zoom must be within 2%, subject width/height within 8% and position within 0.05 normalized aspect-correct distance, with the tracked label, confidence >=0.65, safe important regions and stable camera. The first qualifying observation pauses the ramp. Only subsequent fresh observations with `isRampingVideoZoom == false`, spanning >=0.2 seconds, confirm completion. A command being sent/accepted is not completion. A current frame can complete without zoom only when the fresh measured composition explicitly chooses the current crop, subject scale/position/visibility/light are acceptable and a stable hold succeeds. Landscape scene readiness additionally needs fresh scene evidence and measurements. Unmeasured centering cannot enter READY. Normal photo capture remains available outside the active zoom/verification phase; automation does not fake preview scaling.
