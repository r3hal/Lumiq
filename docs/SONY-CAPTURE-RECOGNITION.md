# Focal 1.8 / build 11 — Sony capture recovery and richer local guidance

## Evidence

The user shows a working Sony preview of printed card boxes with Camera alerts containing Sony: 5 and Sony: 40400, reports an intermittent disconnect with uncertain wording, and asks for substantially better guidance. The user confirms these occurred when pressing the shutter. The prior capture path sent only actTakePicture as its shutter command, identifying that command as the refused/failed operation. The feedback still does not prove a physical cause. Code inspection shows this Camera alert promotes capture/transfer failures, while Sony touch focus previously only set a connection message. Focal fired actTakePicture without refreshing availability, preparing focus, waiting for still mode, or following a pending capture. A stream ending during a photo also cancelled the entire control operation. These are concrete implementation gaps, not hardware confirmation of a repair.

Public Camera Remote API implementations identify 40400 as shooting failure (including failure to obtain focus) and 5 as an illegal/refused request in the current state. See [error constants](https://github.com/shigeosa/ofxSonyRemoteCamera/blob/21c94f851bc15b3bad04f2ae66aed99ca81e75df/src/ofxSonyRemoteCamera.h) and [focus preparation / pending-capture example](https://github.com/fpt/sony-qx-camera/blob/f547ba03bd0c7c59491e0fb2fa07ad7871d5f47a/src/qx10/api.py). Neither proves that focus was the cause on this user's A7 III.

## Capture and connection changes

- Typed errors retain method, numeric code and actual camera detail, with concrete focus/card/mode recovery instead of a bare number and trailing dot.
- Before a shutter command, refresh available controls and reported state. Do not change mode or shoot during a reported movie/capture/transfer operation. If Sony reports a different idle shoot mode, request still only when it advertises that option and setter, then wait for capture availability.
- Prepare a remote half press when currently available and the paired release is advertised either as available or in the camera's actual method table. Skip native MF; wait briefly for reported focus. A reported focus failure releases the half press and does not fire. An explicitly refused optional half press can fall back to one normal capture. Release on completion/error/close where supported.
- Exactly one actTakePicture per user press. Error 40403 follows the original capture using advertised awaitTakePicture. Timeouts and ambiguous connection failures never replay the shutter. Errors after a command/transfer explain that a photo may already be on the card.
- Serialize touch focus without queueing repeated taps; pause telemetry polling while focus/capture is active. Refresh current method/state availability approximately every two seconds instead of keeping an initial capability snapshot forever.
- Local Sony sessions disable cellular routing. This does not rejoin Wi-Fi or change iPhone network settings.
- On interrupted/stalled live view, try at most three reconnects with 1/2/4-second backoff. Retry count resets after 20 seconds of healthy streaming or an explicit user connection. Pause/disconnect cancels recovery; resume avoids restarting an already active session. Permanent setup/control errors still report their problem.
- If stream transport ends during a still capture, clear the preview but preserve the control/transfer operation, then reconnect after it finishes. Recovery never takes another photo. Clear stale guidance on stream loss/capture and skip Sony analysis during capture.

## Subject recognition

The old acquisition required a high-scoring specific image-classifier label on objectness regions and used 640-pixel crops. It can miss printed products that Apple classifies weakly or broadly.

This update keeps actual people/face/pet detectors and objectness proposals, and classifies object crops from the existing bounded 1280/1600-pixel detail copy. No full-resolution native iPhone buffer is retained. Canonical classifier synonyms avoid resetting acquisition between Keyboard/Keypad, and broad furniture/room labels do not hide a supported specific prediction. Predictions at 0.45–0.6 require a larger competing-class margin and stronger spatial separation; every automatic product still needs repeated identity, measured bounds and relevance. Confidence is not added across synonymous labels.

For nonsemantic acquisition, use accurate local text recognition and up to four real rectangle detections. Printed words must lie predominantly inside an actual rectangle or objectness region. Card/deck terminology can support a specific card label, e.g. visible BELOT → Belot cards. Other readable headings are shown literally as a print, e.g. “SOLSTICE” print; arbitrary text does not imply a brand/product type. Weak, repeating and generic text cannot create an identity. Readable printed detail is not penalized like anonymous texture. Rectangle crop classification remains a bounded fallback when text does not identify a region. Names can still be wrong; these are local detector/classifier/OCR heuristics, not universal visual understanding or a measured multiplicative improvement.

## Guidance

Existing real subject boxes, target ring, pan direction, confidence/loss guards and temporal debouncing remain. Core guidance now measures exposure inside the chosen region once per second and background edges separately. It prioritizes space/crop/movement/alignment, then clipped highlights, low subject light and clutter, before Great framing. Examples: Pan right · place the Belot cards on the mark; Add soft light to the Belot cards; Change your angle to separate the Belot cards. Printed/card subjects receive relevant face/edge suggestions. Search can explain poor measured light without inventing a subject.

A black background alone does not imply poor subject exposure. Searching is gray, adjustments are yellow, and the green target check requires the actual ready guidance state. Suggestions do not certify optical focus, intent or artistic quality. Sony roll still does not use the phone's sensor; lens zoom/exposure remain on the camera. No preview/capture pixel upscaling, cloud AI or image uploads were added.
